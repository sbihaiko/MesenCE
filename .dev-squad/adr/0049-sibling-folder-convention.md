# ADR-0049: Convention over configuration — the sibling folder is the pack

- Status: accepted (F5.1, 2026-08-25)
- Date: 2026-08-25
- Phase 5 (docs/roadmap/plano-execucao-F5.md). Supersedes the manifest-heavy
  drafts of ADR-0045/0046/0048 (deleted 2026-08-27; their text lives in git history, the surviving substance is summarised here).

## Context
Two real packs (Contra80s, Zelda Remastered) showed authors fighting text
manifests and coordinates. The user's direction: fewer mappings, more
conventions — *running a game should produce a folder next to the ROM, with
the ROM's name, holding automatically optimised textures and audio; an artist
bootstraps from that folder.*

## Decision
### 1. Location and identity
For `<dir>/<Game>.nes` the pack is `<dir>/<Game>/`. No `pack.json` needed:
the host derives the target hash from the ROM beside it and the system from
the ROM. A `pack.json` is **optional** and only adds metadata (name, author,
license, extra `targets[]`) when the author wants to publish the folder as a
MEP zip — `mep pack` writes it from the folder.

**The local folder always wins.** Discovery order (revises ADR-0040):
**sibling folder** `<dir>/<Game>/` → `HdPacks/<Game>/` (legacy) →
`EnhancementPacks/` containers (folders and zips). An artist working in the
sibling folder never has to uninstall or disable an installed zip of the same
pack: whatever is beside the ROM is what plays. If the ROM's directory is not
writable, the bootstrap is written to `EnhancementPacks/<Game>/` instead and a
notice says so.

**Zip = the folder, zipped.** `<Game>.zip` (the sibling folder compressed
as-is, no `pack.json`) is accepted in `EnhancementPacks/` and matched by the
same rule as the folder: name equal to the ROM's name. `pack.json` remains
optional metadata for publishing to other people (hash-based matching for any
file name, credits, license); `mep pack` writes it.

### 2. Fixed layout — the folder tree is the manifest
```
<Game>/
  textures/            # artist layer: anything here beats auto/
    hires.txt          # generated by `mep build`, never hand-edited
    sheets/            # editable sprite/tileset sheets (PNG)
  audio/
    bgm/<track>.ogg    # artist replaces files, same names
    sfx/<id>.ogg
    midi/<track>.mid   # raw material (read-only for artists)
    stems/<track>_ch<n>.wav
  synth/preset.cfg     # ESP overrides
  auto/                # regenerated freely by the emulator; never edit
    textures/  audio/  synth/
  .bootstrap           # generator version + ROM sha1 + timestamps
```
Notes on the layout:
- `textures/hires.txt` "generated by `mep build`" is author-side tooling the
  author invokes on their own sheets; it is distinct from host-initiated
  automation (bootstrap/regeneration), which only ever writes inside `auto/`.
  This is how the tree above coexists with MEP-v1 §2.1 rule 6 ("everything
  outside `auto/` belongs to the author and MUST NOT be altered by automated
  tools").
- The canonical minimal layout is MEP-v1 §2.1 rule 6 (`textures/hires.txt`,
  `audio/hires.txt` or `audio/fingerprints.json`, `synth/preset.cfg`, and their
  `auto/` mirror). The extra folders shown above (`sheets/`, `midi/`,
  `stems/`, `.bootstrap`) are authoring material that hosts ignore.
- **Two layers, by folder**: top-level = human (`art`), `auto/` = machine.
  Precedence per entry: top-level > `auto/`. No layer ids, no toggles beyond
  "use auto layer" (global) and "use sibling packs" (global). *Open tension,
  not resolved here:* MEP-v1 §5 requires hosts to offer a toggle independent
  per section; whether the sibling-folder pack is exposed with the usual
  per-section toggles (ADR-0040's model) or §5 gains an exception for
  convention-form packs is still to be decided.
- **Provenance by location**: a file under `auto/` is machine-made; a file
  outside it is human-made. Regeneration only ever writes inside `auto/`.
- **Names are keys**: `bgm/<track>.ogg` maps to the `<bgm>` entry of the same
  track id; `sheets/<object>.png` cells map to tile keys through the sheet's
  order, recorded in a comment header inside the generated hires.txt.

### 3. Trigger
Setting *"Bootstrap enhancement folder for played games"* (default **on**).
On load, if `<Game>/` has no `.bootstrap` or its generator version is older,
the emulator: exports ROM tiles (ADR-0043), records tiles + MIDI/VGM while the
user plays (rolling, bounded), and on unload/power-off runs the auto steps
(upscale, segment, fingerprint, render) into `auto/`. Second load already
plays with the auto layer. Everything human stays untouched.

## Consequences
- Zero configuration for players; a pre-organised workspace for artists.
- The folder is the *authoring* form, the zip the *distribution* form; both
  load, the folder takes precedence over any installed zip.
- Name-based matching (folder or zip named like the ROM) is deliberately
  looser than hash matching — same trade-off the legacy `HdPacks/<rom>/` makes.
- Library folders get one subfolder per played game — this is the intended
  trade-off; the setting turns it off.
- Rendering audio needs external tools (fluidsynth); when missing, `auto/audio`
  gets MIDI only and the log says what to install.
