**Diagnóstico (scout/spec):** Identified in: scripts/validate_palette_variants.py
**Por que falhamos / como evitar:** Esse bug existiu porque o harness Python assumiu implicitamente que "binário existe" == "binário atualizado" — ensure_capture_tool() só chama `make capture-tool` quando o arquivo está ausente, nunca quando está desatualizado em relação ao MesenCore.dylib/fontes que ele linka. É uma classe de erro de staleness de artefato de build não rastreado por git (scripts/headless_record está no .gitignore, então não há timestamp de commit para comparar, só o do disco local). O sintoma (SIGABRT por símbolo dyld ausente, antes de qualquer código do HdPackBuilder rodar) foi fácil de mal-diagnosticar como bug de lógica em HdPackBuilder porque o AC-3 só reporta "processo abortou durante a gravação", sem distinguir falha de carregamento dinâmico de falha em tempo de execução real. Teria sido evitado comparando mtime do binário contra o mtime do .dylib (ou simplesmente sempre invocando `make capture-tool`, que já é idempotente e sempre relinka porque o alvo não corresponde a nenhum arquivo e este Makefile não declara .PHONY) em vez de um teste de existência.
